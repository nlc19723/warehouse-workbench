## 一、Step 5 账号体系（约 1.7 人日）

### 1.1 数据模型：库管员账号

```js
// 存储：localStorage 键 wb_keepers；云端 settings.json 键 wb_keepers（多设备共享）
[{
  id: 'k-xxxx',           // 唯一 ID
  name: '张三',            // 用户名（登录用，创建后不可改 —— 见 1.7 说明）
  pwdHash: 'sha256(...)',  // 密码哈希（是否加盐见待拍板 #1）
  salt: '随机串',          // 若采用加盐方案

  createdAt: 'ISO',
  disabled: false          // 禁用而非物理删除（见 1.7）

```

```js
{ name: '张三', role: 'keeper', loginAt: 'ISO' }
```

### 1.4 库管员账号管理（管理员面板）

在 `openAdminPanel()`（`app.js:521`）**末尾追加**「👥 库管员账号」区块：

| 功能 | 交互 |
|---|---|
| 账号列表 | 只显示用户名 + 状态（启用/禁用），**不显示密码** |

### 1.5 盘点人自动带出

`stocktake.js` 中盘点人目前是手填（`task.counter`，多处引用：renderTable 输入框、行显示、保存/结束逻辑）。改为：

```js
// render() 进入模块时
const u = AppConfig.getCurrentUser();
if (u && !this.task.counter) this.task.counter = u.name;
```

| 场景 | 行为 |
|---|---|
| 已登录 | 自动填充当前账号名（**是否锁定为只读，见待拍板 #2**） |
| 未登录 | 留空，手填（兜底，不阻塞使用） |

> 这正是当初"留接口"的价值：盘点模块只调 `getCurrentUser()`，登录体系怎么实现都不影响盘点主逻辑。

### 1.6 云端同步（多设备共享账号）

```js
setKeepers(list) {
  localStorage.setItem('wb_keepers', JSON.stringify(list));
  // 异步同步云端；失败仅告警，不阻塞
  if (typeof DataStore !== 'undefined' && DataStore.setSetting) {
    DataStore.setSetting('wb_keepers', list);
  }
}
// 启动时：本地为空则从云端拉回
```

⚠️ 注意：`settings.json` 是**读-改-写整体覆盖**（`sync.js:445` 注释已说明两台设备并发写不同 key 会互相抹掉），v208 已加回读重试。账号变更是低频操作，可接受。

### 1.7 两个必须注意的设计点

**① 用户名创建后不可改**
盘点记录里存的是 `盘点人: '张三'`（字符串）。若改用户名，历史记录的归属就断裂了（查不到这个人）。所以：**用户名不可改，只能禁用/删除/重置密码**。

**② 优先"禁用"而非"物理删除"**
删除账号后，历史盘点记录里的名字仍在，但账号不存在 → 记录模块按盘点人筛选时该名字仍可选，却不对应任何账号。建议默认**禁用**（保留历史归属），删除需二次确认并明确提示。

## 二、Step 6 打磨与发布（约 1.7 人日）

### 2.1 差异着色（盘点表格）

现状：盘点记录模块的差异量已有绿/红着色，但**盘点表格**的差异量列（stocktake.js:272 `.st-diff`）**还没有**。补齐：

| 差异 | 颜色 |
|---|---|
| 盘盈（> 0） | 绿 `#16a34a` |
| 盘亏（< 0） | 红 `#dc2626` |
| 无差异 / 未填 | 默认灰 |

### 2.2 键盘流（提升盘点效率）

盘点数量输入框增加：

| 按键 | 行为 |
|---|---|
| `Enter` | 跳到**下一未盘行**并聚焦（连扫连录的核心体验） |
| `↑` / `↓` | 上/下移动焦点 |
| 扫码命中后填数 | 自动跳下一未盘行 |

> 现状：扫码已能定位并聚焦（`focusRowByCode`），但**填数后不会自动跳下一行** —— 这是"连扫连录"体验的最后一环，本期补上。

### 2.3 盘点记录「编辑」

盘点记录是**追加型数据**（只增不改）。所以"编辑"的正确实现是：

> **作废原记录 + 新增一条修正记录**（保留追加语义与审计痕迹），而不是直接 UPDATE 历史记录。

- 操作列新增「编辑」按钮（与「作废」并列）
- 弹窗修改：盘点数量、备注
- 保存时：原记录 `voided=1`，新增一条并在备注标注 `由【原值 X】修改为【新值 Y】`
- 差异量按新盘点数量重算

### 2.4 出库列表改名

`index.html:131`：
```html
<!-- 仅改显示文字，data-module 与逻辑完全不变 -->
<span class="item-text">出库列表</span>  →  <span class="item-text">🏬 中心库房出库单列表</span>
```

> 已确认你只有单库房（云端 stock 全部 1407 条均为「中心总库」），所以直接复用现有模块、只改名即可，无需加库房字段。

### 2.5 复核出库量取数

确认日常盘点的【出库量】列来自 `DataStore.getOutbound({startDate, endDate})` 聚合（Step 2 已实现），与「中心库房出库单列表」同源，改名后口头对齐即可，无需改代码。
