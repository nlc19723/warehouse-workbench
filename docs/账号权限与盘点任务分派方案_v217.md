## 一、盘点三层架构（核心改造）

### 1.1 现状

当前只有两层，且职责错位：

| 模块 | data-module | 现状职责 | 问题 |
|---|---|---|---|
| 盘点 | `stocktake` | **执行**（填数/保存/结束） | ✅ 正确 |

| —— | —— | —— | 缺批次级汇总模块 |

### 1.2 改造目标（v217）

拆成**职责清晰的三层**：

### 2.4 盘点结束时的生成逻辑（已按审查结论修正）

> ⚠️ **初版此处有多个会导致汇总算错的错误，已按源码逐条修正。** 详见 §12 审查记录（#1 #2 #5 #9 #11 #14）。

`finishStocktake()` 末尾追加（**不传 `recs`**，内部自行读取全批次数据）：

```js
async _generateBatchSummary() {
  if (!this.sheet) return;
  const sheetId = this.sheet.sheetId;

  // ① 防覆盖：已有快照则不覆盖（多人先后结束时，以先生成的为准）
  const exist = await DataStore.getStocktakeBatch(sheetId);
  if (exist && !exist.voided) {
    this.toast('该批次汇总已由 ' + exist.generatedBy + ' 于 ' +
               String(exist.savedAt).slice(0, 10) + ' 生成。如需重算，请联系管理员在汇总模块点「重新生成」');
    return;
  }

  // ② 应盘全集：按 sheetId 重新计算（不依赖 allRowsFull —— 见审查 #2）
  const totalCodes = await this._calcBatchTotalCodes();

  // ③ 已盘：读该批次全量记录（pull 合并后，含所有人的 —— 见审查 #1）
  const allRecs = await DataStore.getStocktakeRecordsBySheet(sheetId);
  const validRecs = (allRecs || []).filter(r => !r.voided);

  // 区分「实盘」与「结束时补 0」：closedByFinish=1 表示人没盘、系统按 0 计入（见审查 #9）
  // 若混为一谈，覆盖率会虚高至 100%，与「未盘清单」自相矛盾。
  const realRecs = validRecs.filter(r => !r.closedByFinish);
  const zeroRecs = validRecs.filter(r => r.closedByFinish);
  const countedSet = new Set(validRecs.map(r => r.存货编码));   // 账面已平（含补0）
  const realSet   = new Set(realRecs.map(r => r.存货编码));     // 真人盘过

  // ④ 盘盈 / 盘亏（差异量已按 BUG-B 修过精度）
  //    注意：补 0 记录的差异量 = −现存量，天然全判为盘亏，属预期行为，不剔除。
  let profit = 0, loss = 0;
  validRecs.forEach(r => {
    const d = Number(r.差异量) || 0;
    if (d > 0) profit += d; else if (d < 0) loss += Math.abs(d);
  });

  // ⑤ 各人进度（done 来自记录；assigned / status 来自任务）
  //    done 含该人「结束时补 0」的行 —— 补 0 即表示该人已交卷，不会再盘，计入进度合理。
  const byCounter = {};
  validRecs.forEach(r => {
    const c = r.盘点人 || '未知';
    byCounter[c] = byCounter[c] || { done: 0 };
    byCounter[c].done++;
  });
  const batchTasks = await DataStore.getTasksBySheet(sheetId);
  this._batchTasks = batchTasks || [];        // 供 _genBatchName() 取分配日（见 §2.7）
  (batchTasks || []).forEach(t => {
    if (!byCounter[t.counter]) byCounter[t.counter] = { done: 0 };
    byCounter[t.counter].assigned = t.codes ? t.codes.length : (t.noEnd - t.noStart + 1);
    byCounter[t.counter].status = t.status;
  });

  // ⑥ 未盘清单（分派模式可判归属，认领模式诚实标注未知 —— 见审查 #4）
  const uncounted = [...totalCodes].filter(c => !countedSet.has(c));
  const openTasks = (batchTasks || []).filter(t => t.status === 'open');
  const uncountedCodes = uncounted.map(code => {
    const t = openTasks.find(t => t.codes && t.codes.includes(code));
    if (t) return { code, reason: 'assigned', assignee: t.counter };
    return { code, reason: openTasks.length ? 'unassigned' : 'unknown', assignee: null };
  });

  // ⑥b 「补 0 计入」清单：账面已平，但人没真盘过 —— 单独列出，不算进未盘也不算实盘
  const zeroFilledCodes = zeroRecs
    .filter(r => !realSet.has(r.存货编码))
    .map(r => ({ code: r.存货编码, assignee: r.盘点人 || null }));

  const summary = {
    sheetId,
    batchName: this._genBatchName(),          // 见 §2.7
    sheetType: this.sheet.sheetType,
    startDate: this.sheet.startDate,
    endDate: this.sheet.endDate,
    total: totalCodes.size,
    counted: realSet.size,             // 实盘数（真人盘过）
    zeroFilled: zeroFilledCodes.length,// 补 0 数
    uncounted: uncounted.length,       // 真未盘数
    realCoverage:  totalCodes.size ? realSet.size / totalCodes.size : 0,      // 实盘覆盖率
    bookCoverage:  totalCodes.size ? countedSet.size / totalCodes.size : 0,   // 账面覆盖率（含补0）
    profit: round2(profit),
    loss: round2(loss),
    byCounter,
    uncountedCodes,
    zeroFilledCodes,
    savedAt: new Date().toISOString(),
    generatedBy: this.task.counter,
    deviceId: this._deviceId(),
    voided: 0
  };

  await DataStore.addStocktakeBatch(summary);
  await this._pushBatchToCloud(summary);
}

// 按批次重新计算应盘全集（抽自 startDaily:79 / startQuarter:126 的筛选段，只取编码不渲染）
async _calcBatchTotalCodes() {
  const { sheetType, startDate, endDate } = this.sheet;
  const stock = await DataStore.getStock();
  const codes = (stock || [])
    .map(s => String(s.存货编码 == null ? '' : s.存货编码).trim())
    .filter(Boolean);
  if (sheetType === 'quarter') return new Set(codes);   // 季度 = 全库
  // 日常 = 只保留区间内有出库的（复用 _aggByCode 聚合逻辑）
  const out = await DataStore.getOutbound({ startDate, endDate }, 1, 1000000);
  const outMap = this._aggByCode(out && out.items ? out.items : (out || []), '数量');
  return new Set(codes.filter(c => outMap[c] > 0));
}
```

### 2.6 进行中批次的实时计算（补审查 #3 的缺口）

**问题**：快照只在"结束"时生成。若批次还在进行中（有人保存了但没点结束），汇总模块里**根本不存在这个批次** → 管理员看不到进度，与 §5.4「管理员查看各人进度」直接矛盾。

**解决**：汇总模块的批次列表 = **快照 ∪ 实时计算的进行中批次**。

```
批次列表 =
  ① 已结束：batches 里的快照（固定不变，永久翻查）
  ∪
  ② 进行中：有 records 但无快照的 sheetId（每次进模块实时聚合，不落库）
```

| 维度 | 已结束（快照） | 进行中（实时） |
|---|---|---|
| 数据来源 | `batches[sheetId]` | 实时读 `records` 聚合 |
| 是否落库 | ✅ 是（永久） | ❌ 否（每次现算） |
| 数值会变吗 | ❌ 定格不变 | ✅ 随保存实时更新 |
| 列表标记 | 「已结束 · 08-31 · 由张三生成」 | 「进行中 · 已盘 30/100」 |
| 作废 / 重新生成 | ✅ 管理员可 | ❌ 无此操作 |

两者用**同一个卡片组件**渲染，只是数据来源不同。这样管理员随时看得到进度，结束后又能定格成永久档案。

**进行中批次的四个技术要点：**

1. **sheetId 来源**：从本地 `records` 里 `distinct(sheetId)` 得到，无需 tasks 存在。
2. **⚠️ 应盘全集（total）怎么算**：`_calcBatchTotalCodes()` 依赖 `this.sheet`，而汇总模块没有 sheet 对象。需抽成独立函数，从 sheetId 反解：
   ```js
   // sheetId 形如 quarter_08-02_08-31（MM-DD，无年份 —— 见审查 #14）
   function parseSheetId(sheetId) {
     const m = /^(daily|quarter)_(\d{2}-\d{2})_(\d{2}-\d{2})$/.exec(sheetId || '');
     if (!m) return null;
     const y = new Date().getFullYear();          // 年份需补：用当前年
     return { sheetType: m[1], startDate: y + '-' + m[2], endDate: y + '-' + m[3] };
   }
   async calcTotalCodesBySheetId(sheetId) { /* 复用 _calcBatchTotalCodes 的筛选段 */ }
   ```
   > 跨年批次（如 `quarter_12-25_01-05`）按此补年会算错。当前批次周期最长一个季度，且 sheetId 起止同号段，**已存在的历史数据全部在同年**，暂不处理；若后续要做跨年批次，需在记录里补 `sheetYear` 字段。
3. **不落库**：每次进模块现算，退出即丢，避免产生"半截快照"。
4. **无「重新生成 / 作废」按钮**：进行中批次本就是实时值，重算无意义。

### 2.7 批次命名规则

**需求**：批次用"日常盘点那天"或"季度盘点分配那天"命名。

**约束**：`sheetId` 是数据键（`${type}_${start}_${end}`），**不能改** —— 改了会让云端已有的 5 条记录和 tasks 全部断链。所以**新增显示名字段 `batchName`**，`sheetId` 保持不动。

| 场景 | 命名依据 | 示例 |
|---|---|---|
| 日常盘点 | 盘点那天（结束当日） | `2026-08-31 日常盘点` |
| 季度盘点 · **分派模式** | **分配那天**（管理员建任务的日期） | `2026-08-30 季度盘点` |
| 季度盘点 · 认领模式 | 盘点那天（无分配日可依） | `2026-08-31 季度盘点` |

**⚠️ 前置依赖（审查 #5）**：`createdAt` 当前只在**结束**时写入（`stocktake.js:598`），直接拿它会取到"结束那天"，命名规则失效。必须先在分派时写入：

| 时机 | 写入 | 说明 |
|---|---|---|
| 管理员分派任务时 | `createdAt = 分配当天` | **新增**，见 §5.2 任务结构 |
| 库管员点【结束】时 | 只更新 `status` / `closedAt` | **禁止覆盖 `createdAt`** |
| 认领模式（无 task） | 无 `createdAt` | 回退到盘点当天 |

```js
_genBatchName() {
  const typeCn = this.sheet.sheetType === 'quarter' ? '季度盘点' : '日常盘点';
  let d;
  if (this.sheet.sheetType === 'quarter') {
    // 优先取分派日：查该批次本人任务的 createdAt（由管理员分配时写入）
    const t = (this._batchTasks || []).find(t => t.counter === this.task.counter);
    d = (t && t.createdAt) ? String(t.createdAt).slice(0, 10) : this._today();
  } else {
    d = this._today();          // 日常 = 盘点那天
  }
  return d + ' ' + typeCn;
}
```

> `this._batchTasks` 由 §2.4 步骤 ⑤ 赋值（`this._batchTasks = batchTasks || [];`），此处直接复用，不再额外拉一次。

**重名处理**：同一天同类型可能盘多次（如上午下午各盘一轮）。
- 列表主标题显示 `batchName`，副标题灰色小字显示 `sheetId`（起止日期）→ 天然可区分
- 若 `batchName` 完全重名，自动追加序号：`2026-08-31 日常盘点 (2)`

## 五、盘点任务分派

### 5.1 两种模式共存

| 模式 | 触发 | 行为 |
|---|---|---|
| 分派 | 有指派给他的 open 任务 | 顶部"我的任务"下拉，选中后锁定人和区间（只读），直接渲染 |
| 认领 | 无分派任务 | 回退现有：自填名字+自选区间 |

### 5.2 固化编码清单

分派时把该区间的存货编码写进 task（`codes` 数组），库管员端按 codes 渲染，序号=下标。**与全库排序彻底解耦**，支持挑着分派。

```js
tasks[taskId] = {
  taskId, sheetId, sheetType, counter, noStart, noEnd,
  status: 'open',
  codes: ['A001', ...],           // 固化
  anchorFirst: 'A001', anchorLast: 'A100',
  createdAt: '2026-08-30T...',    // 【新增】分配时刻，供批次命名取「分配那天」（见 §2.7）
  closedAt: null
}
```

**两个写入纪律（否则会出 bug）：**

| 纪律 | 说明 |
|---|---|
| ① `createdAt` 只在**分配时**写一次 | 结束时**不得覆盖**；否则批次命名会变成"结束那天"（审查 #5） |
| ② 云端 task 用**合并**而非覆盖 | 现 `sync.js:556` 是 `tasks[taskId] = taskPatch` **整体覆盖**，会抹掉已存的 `codes`/`createdAt`。必须改为 `tasks[taskId] = Object.assign({}, tasks[taskId] || {}, taskPatch)`（审查 #6） |

> `taskId` 由 `sheetId + counter + 序号区间` 组成（`stocktake.js:531`）。**同一个盘点人改名会产生新 taskId**，故分派后不宜再改账号名。

### 5.3 分配给管理员自己

管理员密码验证通过后写特殊会话 `{username:'管理员', role:'admin'}`。分派下拉出现"管理员"；管理员进盘点模块自动带出"管理员"作为盘点人。

只改验证**之后**的会话写入，不碰 `getAdminPwdHash()`。

### 5.4 进度查看

任务列表显示 `已盘/总数`，读云端 records 按 counter 聚合。

async _connect() {
