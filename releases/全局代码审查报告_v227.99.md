## 2. 绿灯基线（已验证健康，无需改动）

以下项经代码级核查**确为健康**，作为本次审查的基线，避免重复造轮子：

- **XSS 转义链路完整**：`esc()`（`js/config.js:453`）实现为 `String(v).replace(/[&<>"']/g, ...)`，覆盖五大注入字符；`escAttr` 复用 `esc`。明细表渲染（`stock-detail.js:225`、`supplier-detail.js:191`）对 `head`/`body` 均套 `esc`；所有列表/明细的交叉链接统一走 `TableUtils.link()`（`js/table-utils.js:1747`），其内部对 `type/key/text` 三者分别 `escAttr`/`esc`，**供应商名、存货名称、订单编号等导入数据均无裸注入点**。
- **导入数据弹窗安全**：`data-loader.js` 的 5 处 `innerHTML`（729/882/893）均为静态 UI 模板（导入说明、云端备份布局），无用户数据插值 —— 静态扫描缺口为误报。
- **事务原子性**：`clearAll()`（`js/db.js:224`）用 `db.transaction('rw', …)` 包裹 12 表清空，中途抛错整体回滚（AUDIT-002）；所有写路径经 `DataStore.write()` 统一入口（`js/db.js:194`），写后自动失效内存缓存（AUDIT-101）；云端恢复路径（`restoreOutboundFromSettings` 等，`js/db.js:316-356`）的 `clear()+bulkPut` 均包在 `write()` 事务内 —— 无"半清库/覆盖丢数"风险。
- **性能**：`getRows()`（`js/db.js:177`）已做内存缓存；大 Excel 解析经 `new Worker('js/import-worker.js')`（`js/data-loader.js:686`）后台线程，不阻塞主线程；列表查询走 `db.orders.where('供应商').equals()` 索引（`js/supplier.js:290`）而非全表扫描。
- **事件绑定无 SPA 泄漏**：`qr-util.js:203` 用 `document` 级事件委托（模块加载即绑一次，靠 `closest` 命中，刻意全局生效）；`order-check.js:301` 用 `if (!this._docClickBound)` 幂等守卫只绑一次；`datepicker` 用 `AbortSignal` 自动解绑。**未发现有模块反复进入导致 addEventListener 累加的真实泄漏**。
- **全局符号无冲突**：99 个顶层全局中，排除 `globals.js` 的 `window.X = X` 导出桥后，**真实跨文件重复定义 = 0**。所有"重复"均为「`const X` 定义（模块顶部）+ `window.X = X` 导出桥（模块尾部/全局桥）」的健康模块化模式，历史上踩过的同名覆盖坑未复现。
- **静默失败兜底**：`globals.js:58-62`（AUDIT-004）已注册 `unhandledrejection` + `error` 全局监听，统一 console 留痕，使无 catch 的 await 失败至少可见。
- **双视口冒烟**：桌面 + 移动均 **0 console error / 0 pageerror**；`App/AppConfig/SyncManager/DataStore/db/esc/TableUtils/DataLoader/WBModal` 全部就绪；`SyncManager.isOnline === true`（云端开机自动连接按需求生效）。

## 3. 问题清单（按严重度分级）

> 严重度：🔴 P0 阻断 / 🟡 P1 高 / 🟢 P2 中 / ⚪ P3 低
> 本次**未发现 P0/P1 级阻断缺陷**，问题集中在 P2（体验）与 P3（优化）。

### LOGIC-001 🟢 P2 · 逻辑Bug / 静默失败
- **位置**：全仓约 205 处 `await` 无就近 `catch`（见 `audit-inventory.json → awaitNoCatch`）
- **频率**：中　**影响**：广（涉及导入/同步/保存等用户关键操作）
- **触发场景**：导入中途网络抖动、Supabase 超时、Dexie 写异常
- **证据**：`js/data-loader.js` 导入链路、`js/sync.js` 云端上传/下载链路、各模块 `render` 内 `await` 多无 try/catch
- **后果**：虽有 AUDIT-004 全局兜底（console 留痕），但**用户层无 Toast 提示**——失败操作界面可能停留在"成功"态或陈旧数据，用户误以为数据已落库/已同步
- **修改方案**：在关键写路径（`DataLoader` 导入、`SyncManager` 上传、`DataStore.write` 调用点）显式 `try/catch` + `WBModal.toast('操作失败：'+e.message, 'error')`；fire-and-forget 后台同步（`_syncAssignedTasks` 等）维持现状即可

### SEC-001 🟢 P2 · 安全 / XSS 加固（当前无实际漏洞）
- **位置**：全站高频内联事件，如 `js/table-utils.js:1753` `onclick="App.openEntity('${t}','${k}')"`
- **频率**：低　**影响**：窄（攻击面高杠杆，但当前已转义）
- **触发场景**：若未来某处新增渲染点遗漏 `escAttr` 包裹用户数据即构成存储型 XSS
- **证据**：`escAttr` 当前覆盖 `&<>"'`，故 `k` 注入被拦；但内联拼接属"一处疏漏全站沦陷"的高杠杆结构
- **后果**：潜在存储型 XSS（供应商名/存货名等可被构造的导入数据触发）
- **修改方案**：将交叉链接从内联 `onclick` 迁移为 `document` 级事件委托（参考 `qr-util.js` 已落地的委托模式），用 `data-*` 属性传参，彻底消除内联拼接攻击面

### PERF-001 ⚪ P3 · 性能 / 大规模数据
- **位置**：`js/db.js:182` `db[table].toArray()`
- **频率**：低（仅首屏/失效后）　**影响**：中（10 万行级数据）
- **触发场景**：单表 10 万行，`getRows()` 首次加载需全表读入内存并驻留
- **证据**：缓存命中后走内存，但首屏冷加载与 `invalidateAll()` 后仍全量 `toArray`
- **后果**：首屏耗时随数据量线性增长、内存占用高
- **修改方案**：超大数据量表列表渲染改 IndexedDB 游标/offset 分页查询，避免一次性全表驻留；当前为设计权衡，非阻断

### DATA-001 ⚪ P3 · 数据完整性 / 金额精度边界
- **位置**：金额显示层 `toFixed(2)`（如 `js/stocktake-batch.js` 卡片渲染）
- **频率**：极低（仅特定边界值）　**影响**：窄
- **触发场景**：`(1.005).toFixed(2)` 在部分 JS 引擎返回 `"1.00"` 而非 `"1.01"`（banker's rounding 边界）
- **证据**：关键计算已统一 `round2()`（`js/stocktake.js` 5 处、`js/stocktake-batch.js` 1 处）；但**显示层**仍直接 `toFixed`，未经 `round2` 预规整
- **后果**：极端边界金额显示偏差 1 分
- **修改方案**：显示层统一 `round2(x).toFixed(2)`，消除浮点边界误差

### DEAD-001 ⚪ P3 · 死代码
- **位置**：`js/globals.js:50-51` `window.esc = window.esc;`、`window.escAttr = window.escAttr;`
- **频率**：—　**影响**：窄
- **触发场景**：无（无害）
- **证据**：`esc`/`escAttr` 已在 `js/config.js:453/459` 定义为 `window` 属性，此处自赋值无意义
- **后果**：无功能影响，仅增加阅读噪声
- **修改方案**：删除两行或改为注释说明"已在 config.js 挂载，此处无需桥接"

### QUAL-001 ⚪ P3 · 可维护性 / 硬编码
- **位置**：散落多文件
- **频率**：—　**影响**：窄
- **证据**：多处 `3000` 毫秒超时（如 `js/stocktake.js:84` `_syncAssignedTasks(3000)`）、`'管理员'` 用户名字符串多处比较、`86400000` 等魔法数字
- **后果**：改一处需全局搜替，易漏改
- **修改方案**：提取为 `AppConfig` 常量（如 `ADMIN_NAME`、`SYNC_TIMEOUT_MS`），集中管理

## 5. 结论

当前 **v227.99** 代码库整体**质量健康、可交付**：
- 安全（XSS）经多轮修复已闭环，转义链路完整；
- 数据完整性有事务 + 统一写入口保障，无原子性风险；
- 性能有缓存 + Worker 兜底；事件绑定与全局符号无 SPA 泄漏与冲突；
- 双视口冒烟零报错，核心模块全部就绪，云端开机自动连接按需求生效。

**唯一需重点跟进的是 LOGIC-001（用户无失败提示）**——它不导致崩溃，但会削弱"操作是否成功"的可信度，建议作为下一发版的首个改进项。其余 P3 为体验/可维护性优化，可按节奏处理。
